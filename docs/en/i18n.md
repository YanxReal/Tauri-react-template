# Internationalization (i18n)

> **Audience:** web devs — English (`en`) + Spanish (`es`) via `i18next`.

Bilingual template: **English (`en`) + Spanish (`es`)**. Built with `i18next` + `react-i18next` + `i18next-browser-languagedetector`.

## Files

```
apps/web/src/i18n/
├── config.ts                 # init, resources, detection, fallback
└── locales/
    ├── en.json               # English keys
    └── es.json               # Spanish keys
```

`config.ts:1`:

```ts
import i18n from "i18next"
import LanguageDetector from "i18next-browser-languagedetector"
import { initReactI18next } from "react-i18next"
import en from "./locales/en.json"
import es from "./locales/es.json"

export const resources = {
  en: { translation: en },
  es: { translation: es },
} as const

await i18n.use(LanguageDetector).use(initReactI18next).init({
  resources,
  fallbackLng: "en",
  supportedLngs: ["en", "es"],
  defaultNS: "translation",
  detection: {
    order: ["localStorage", "navigator", "htmlTag"],
    caches: ["localStorage"],
  },
})
```

- `localStorage` cache is `"i18nextLng"` (default key).
- `fallbackLng: "en"` — missing keys fall back to English.
- `htmlTag` order respects manual `<html lang>` overrides.

`App.tsx:29` syncs `document.documentElement.lang = i18n.language` on change.

## Usage

```tsx
import { useTranslation } from "react-i18next"

function MyComponent() {
  const { t, i18n } = useTranslation()
  return (
    <>
      <h1>{t("hero.title")}</h1>
      <p>{t("status.greetFallback")}</p>
      <button onClick={() => i18n.changeLanguage("es")}>ES</button>
      <button onClick={() => i18n.changeLanguage("en")}>EN</button>
    </>
  )
}
```

Interpolation:

```json
// en.json
{ "status": { "tauriNote": "Try Tauri API: {{message}}" } }
```

```tsx
t("status.tauriNote", { message: greet })
```

Greet demo (`App.tsx:37`) translates the Rust string when UI is in Spanish.

## Language toggle

`apps/web/src/components/layout/header.tsx` renders the toggle:

- Calls `i18n.changeLanguage(next)` → updates `localStorage` + `<html lang>` + re-renders via `react-i18next`.
- `aria-label` on the control is translated.

## Adding a locale (e.g. French)

1. Copy `en.json` → `fr.json` and translate values (keep keys).
2. Register in `config.ts`:

```ts
import fr from "./locales/fr.json"
export const resources = {
  en: { translation: en },
  es: { translation: es },
  fr: { translation: fr },
} as const
// supportedLngs: ["en", "es", "fr"]
```

3. Add `fr` to `Header` toggle logic.
4. Duplicate the parity rule: keep `fr.json` key-parity with `en.json`/`es.json` (same structure, no missing keys).

## Adding keys

Add the key to **both** `en.json` and `es.json` at the same path. Use nested objects for grouping (`header.nav.features`, `hero.badge`, `features.items[0].title`). Keep the JSON sorted and flat where reasonable.

## Best practices

- Never hardcode user-facing strings — always go through `t()`.
- Keep keys semantic (`hero.ctaPrimary`) not literal (`button_submit`).
- Avoid `t()` inside `globals.css` or Rust — i18n is frontend-only.
- Test both languages: toggle in `Header` and verify `localStorage:i18nextLng` + `<html lang>`.
