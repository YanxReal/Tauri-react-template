# Internacionalización (i18n)

> **Audiencia:** devs web — inglés (`en`) + español (`es`) vía `i18next`.

Plantilla bilingüe: **inglés (`en`) + español (`es`)**. Hecha con `i18next` + `react-i18next` + `i18next-browser-languagedetector`.

## Archivos

```
apps/web/src/i18n/
├── config.ts                 # init, recursos, detección, fallback
└── locales/
    ├── en.json               # keys en inglés
    └── es.json               # keys en español
```

`config.ts:1`:

```ts
import i18n from "i18next"
import LanguageDetector from "i18next-browser-languagedetector"
import { initReactI18next } from "react-i18next"
import en from "./locales/en.json"
import es from "./locales/es.json"

export const resources = {
  en: { translation: en },
  es: { translation: es },
} as const

await i18n.use(LanguageDetector).use(initReactI18next).init({
  resources,
  fallbackLng: "en",
  supportedLngs: ["en", "es"],
  defaultNS: "translation",
  detection: {
    order: ["localStorage", "navigator", "htmlTag"],
    caches: ["localStorage"],
  },
})
```

- El cache `localStorage` es `"i18nextLng"` (key por defecto).
- `fallbackLng: "en"` — las keys faltantes caen al inglés.
- El orden `htmlTag` respeta overrides manuales en `<html lang>`.

`App.tsx:29` sincroniza `document.documentElement.lang = i18n.language` al cambiar.

## Uso

```tsx
import { useTranslation } from "react-i18next"

function MiComponente() {
  const { t, i18n } = useTranslation()
  return (
    <>
      <h1>{t("hero.title")}</h1>
      <p>{t("status.greetFallback")}</p>
      <button onClick={() => i18n.changeLanguage("es")}>ES</button>
      <button onClick={() => i18n.changeLanguage("en")}>EN</button>
    </>
  )
}
```

Interpolación:

```json
// en.json
{ "status": { "tauriNote": "Try Tauri API: {{message}}" } }
```

```tsx
t("status.tauriNote", { message: greet })
```

La demo de greet (`App.tsx:37`) traduce el string de Rust cuando la UI está en español.

## Toggle de idioma

`apps/web/src/components/layout/header.tsx` renderiza el toggle:

- Llama a `i18n.changeLanguage(next)` → actualiza `localStorage` + `<html lang>` + re-render vía `react-i18next`.
- El `aria-label` del control está traducido.

## Añadir un locale (ej. francés)

1. Copia `en.json` → `fr.json` y traduce valores (mantén keys).
2. Registra en `config.ts`:

```ts
import fr from "./locales/fr.json"
export const resources = {
  en: { translation: en },
  es: { translation: es },
  fr: { translation: fr },
} as const
// supportedLngs: ["en", "es", "fr"]
```

3. Añade `fr` a la lógica del toggle en `Header`.
4. Duplica la regla de paridad: mantén `fr.json` con paridad de keys respecto a `en.json`/`es.json` (misma estructura, sin keys faltantes).

## Añadir keys

Añade la key en **ambos** `en.json` y `es.json` en la misma ruta. Usa objetos anidados para agrupar (`header.nav.features`, `hero.badge`, `features.items[0].title`). Mantén el JSON ordenado.

## Buenas prácticas

- Nunca hardcodees strings visibles — pasa siempre por `t()`.
- Mantén keys semánticas (`hero.ctaPrimary`) no literales (`button_submit`).
- No uses `t()` dentro de `globals.css` o Rust — i18n es solo frontend.
- Prueba ambos idiomas: toggle en `Header` y verifica `localStorage:i18nextLng` + `<html lang>`.
